# 목표 합의·개선 실험·보고 양식

목적: 진단이 실행과 재검토로 이어지게 한다. 대상: 운영자·고객 대표·현장 책임자. 수정일: 2026-10-20. 버전: 2.0. 상태: 내부 시험 템플릿, 계약서 아님·실고객 검증 전. 연결: 4단계 목표→실행→보고. 작성: ChatGPT, 업무·고객 사실·전달 승인: 디테일랩 운영자. 출처: 사용자 지시·기존 베타 범위. 재검토: 첫 합의·실제 사용·중단 사례 발생 때.

## 4단계 공동 목표 합의서 — 빈 양식

프로젝트 코드 / client_id·site_id(연락처 별도) / 목표 ID / 합의 버전 / 대표 결정권자 역할 / 현장 실행자 역할 / 디테일랩 담당 / 확인 날짜 / 자료 허용 범위.

| 질문·항목 | 함께 적을 내용·판단 용도 |
|---|---|
| 무엇이 달라지길 원하나요? | 대표의 최종 결과·이유·우선순위. 매출·직원 변화는 목표이며 제공자 보장 아님 |
| 지금은 어떤가요? | 같은 정의의 기준선·기간·출처·단위. 없으면 수집법·수집 기간부터 |
| 어디까지 확인됐나요? | F/T/H/U 표와 출처 버전, 상충 설명·확인 불가 이유 |
| 이번에 무엇을 다루나요? | 포함 작업·제외 업무·그대로 지킬 강점·전문가 필요 |
| 무엇을 먼저 해보나요? | 한 업무·대상·행동·실제 사용자·선택 이유·다른 대안 |
| 누가 무엇을 맡나요? | 제작·검수·내부 승인·직원 공지·실행·기록·점검 담당 |
| 언제 시작하고 끝나나요? | 자료 충족·권한·양쪽 범위 확인이 시작 조건. 납품/적용/재검토 각각 종료 조건 |
| 시간·비용은 어느 범위인가요? | 건별 견적·납기·현장 소요시간·수정 횟수·연락 방법/한도·취소/지급 조건. 미정이면 시작하지 않음 |
| 무엇으로 변화를 보나요? | 지표 ID/정의버전·계산식·분모·제외·단위·기록자·비교기간·자료 누락 처리 |
| 무엇이 생기면 멈추나요? | 고객 혼선·안전·권한·업무 부담·손실 기준, 즉시 알릴 담당·되돌릴 버전 |
| 언제 다시 보나요? | 중간/종료 점검일·필요 자료·유지/수정/중단 결정권자 |
| 누가 어떤 결과를 책임지나요? | 디테일랩: 합의한 결과물·검수·설명·수정. 고객: 자료 권한·경영 판단·현장 실행 승인. 결과 수치 보장 제외 |
| 자료·AI는 어떻게 쓰나요? | 목적·최소 항목·제출 경로·접근자·보관/삭제일·AI/외부 처리 허용. 기존 동의 자동 확대 금지 |

필수: 진단 표·결정권자·같은 합의 버전 확인. 선택: 담당자 가능 일정·시간 기록·견적·CSV/XLSX 집계. 설명 충돌·가격/자료 권한 미합의면 '합의 대기' 유지. AI는 초안/빠진 항목만 제안, 사람과 대표가 목표·가격·민감 판단·승인을 결정한다. 완료: 두 당사자가 범위·제공물·역할·지표·시간/비용·중단/재점검을 같은 버전으로 확인한다. 법적 계약 조건은 별도 검토한다.

## 문제·가설 기록지

문제 ID / 목표 ID / 언제·어디서·무슨 업무 / 실제 사용자 역할 / 반복 빈도와 관측 기간 / 잘 처리된 비교 사건 / 현행 기준과 버전 / 근거 ID / 당사자 진술 / 다른 설명 / 가설 / 맞지 않을 수 있는 조건 / 반증 자료 / 자료 부족 / 유지할 점 / 다음 질문 / 확인자·확인일.

예: '직원이 책임감이 없다'는 원인으로 쓰지 않는다. '교대 요청 2건에서 완료 표기가 없었다'도 기록이 있어야 F이며, 확인 전에는 T다. '완료 기준이 다르다'는 H로 두고 양쪽에 같은 사례의 완료를 물어 반증한다. 실제 숫자가 없으면 사건 수를 만들지 않는다.

## 실험 기록지와 단계별 완료 기준

| 단계 | 기록 항목 | 다음 상태로 넘어갈 증거 |
|---|---|---|
| 문제 기록 | 장면·기준·근거·강점·제약 | 확인 가능한 사건/미확인 사유, 범위 |
| 가설 | 가능한 설명·대안·반증 | 가설과 사실 분리, 필요한 자료 |
| 계획 | 선택 이유·대상·사용자·행동·담당·승인·예산/시간·지표·기간·되돌리기 | 같은 버전 합의, 자료 권한, 현장 가능 여부 |
| 실행 | 실제 시작일·참여·사용·미실행 이유·예상 밖 반응 | '전달' 아닌 사용 관측/자기보고 구분 |
| 비교 | 기준선·후속·분모·동일 정의·결측·외부 변화 | 비교 가능/불가 표시, 원인 유보 |
| 결정 | 유지/수정/중단·근거·다른 원인·담당·다음 점검 | 대표의 결정과 디테일랩 기여를 각각 기록 |
| 축적 | 버전·보고서·실패·복구·재사용 조건 | 다음 작업이 근거를 다시 찾을 수 있음 |

실험 필드: experiment_id / client_id·site_id / goal_id / problem_id / hypothesis_id / 관련 상품 후보 / baseline_source_id·version / metric_def_version / 변경/유지할 내용 / 사용자 / 실행 담당 / 승인권자 / 시작·종료·점검일 / 예산·예상/실제 분 / 상태 / 사용 증거 / 결과 / 부작용 / 다른 원인 / 결정 / 결정자 / 다음 점검 / report_id.

실패·중단을 삭제하지 않는다. '자료 부족', '미사용', '현장 여건 불가', '효과 관측 안 됨', '부작용', '범위 변경', '고객 중단'을 구분한다. 고객의 승인·직원의 현장 대응·외부 요인·디테일랩 제작/검수의 기여를 따로 적는다. 만족만으로 효과를 확정하지 않는다.

## 주간 보고서 — 복사해서 채우기

- 보고 ID / 고객·목표 코드 / 보고 기간 / 작성·검수·승인·전달 상태 / 포함 자료 ID·버전 / 기준일 / 누락.
- 이번 주 합의한 실행: 계획·실제·미실행 이유·담당·실제 분.
- 사용·반응: 누가 썼는지, 관측/자기보고, 고객·직원 부담과 예상 밖 반응.
- 지표: 정의·단위·원본 기간·값(없으면 미측정)·누락·해석 한계.
- 문제·가설: 새 사건, 이전 가설의 반증, 다른 원인.
- 다음 주: 유지/수정/중단 제안·대표 결정·담당·기한·추가 자료.

완료: 실제/계획 구분, 모든 값에 출처, 다음 담당·날짜, 전달 전 사람 확인. 주간 보고를 만들었다고 실제 적용 완료로 바꾸지 않는다.

## 월간 보고서

기본 머리말은 주간과 같다. ①공동 목표·범위 변경 ②이번 달 결과물·실제 사용·시간/비용 ③기준선과 월간 동일 정의 비교·영업일·분모·결측 ④고객의 만족과 실제 지표 차이 ⑤관련 경제/시장 변화: 기관·표·단위·기준/발표/조회일·지역·잠정/수정·고객 노출·시차·다른 원인 ⑥가설별 지지/반증/판정불가 ⑦대표의 유지/수정/중단 결정 ⑧다음 실험·담당·예산·점검일. 외부 지표가 없거나 관련 없으면 빈 분석을 만들지 않고 '이번 목표와 직접 연결할 자료 없음'으로 쓴다.

## 연간 보고서

①연초/수정 목표와 결정 이력 ②실행·실패·중단 타임라인 ③정의가 이어지는 연간/월별 지표와 정의 변경 전후 분리 ④계절·영업일·가격·구성·지역·시장 변수 ⑤운영 자율성·유지된 업무·인계 상태 ⑥직접비·운영자 시간·유료 수납/환불 별도 ⑦고객의 판단·현장 기여·디테일랩 작업 ⑧계속 쓸 방식·새 문제·다음 검토. 12개월 데이터가 없으면 연간 추세를 추정하지 않고 '확인된 기간만' 표시한다.

## 원격 운영과 범위 관리

원격 가능: 허용된 자료 읽기·인터뷰·문서/양식 제작·CSV 검수·계획·보고·사용 회신. 현장 필요: 실제 동선·안전·서비스 제공 관찰, 도구 접근이 없는 업무. 필요하지만 방문할 수 없으면 현장 책임자의 관찰 기록 또는 해당 전문가를 검토하고 한계를 표시한다. 고객은 공지·현장 승인·적용·자료 확인, AI는 최소 작업본 초안·검수 후보를 맡는다.

합의서에 반드시 채울 수용량 칸: 월 가용시간 / 신규 제작 시간 / 고객당 월 포함시간 / 정기 소통 주기·채널 / 회신 가능 요일·기한 / 수정 횟수 / 긴급 범위 / 초과 요청 처리. 숫자는 실제 제작을 재본 뒤 결정한다. 초기 운영 시험안은 단일 이메일 창구+예약 미팅+월별 작업 목록이며 상시 메신저 대기는 판매하지 않는다. 안전 사고·법적 분쟁·시스템 장애 즉시 대응은 기본 범위가 아니다.

범위 변경 절차: 요청 기록→기존 합의와 차이/영향시간·비용 설명→진행/보류/대체 선택→대표 승인→버전 변경→작업. 승인 전 작업 추가·약속 확대 없음. 월 초과는 조기 알림·다음 달 이월/추가 견적/축소 중 선택한다. 종료 때 최신본·사용법·미해결·권한 회수·자료 보관/삭제일을 점검한다.
