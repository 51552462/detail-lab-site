# 고객 데이터·경제 환경·AI 처리 기준 v2

목적: 자료를 같은 기준으로 축적하고 자동화의 경계를 정한다. 대상: 운영자·개발/검수 담당. 수정일: 2026-10-20. 버전: 2.0. 상태: 데이터 구조 설계·합성 자료용 로컬 실험, 실고객 운영 미승인. 연결: 자료 요청→검수→승인→분석→보고. 작성: ChatGPT. 사람 검수·권한/비용 승인: 디테일랩 운영자. 재검토: 실제 자료 형식·동의·보관·계정·고객 수가 바뀔 때. 법률 판단의 확정 문서가 아니다.

## 최소 구조와 실제 구현 경계

공개 사이트는 정적 파일이다. 기존 GitHub/Notion 연결 접근은 확인했으나 고객용 인증·파일 저장·API 키·유료 플랜·Render 관리 Live SHA는 확인하지 못했다. 새 고객 포털·자동 수집·AI API 연결은 제공하지 않는다.

현재 구현할 검증 단위는 합성 자료 전용 로컬 처리기다. client_id가 SYN-으로 시작하는 테스트만 허용하고, 고객별 별도 SQLite 파일에 사업장·지표 정의·자료 버전·행·검수·보고 이력을 기록한다. 실고객용 인증·암호화·백업·접근 로그 서비스는 아니다. client_id 검사나 로컬 파일 분리만으로 운영 보안을 갖췄다고 말하지 않는다.

| 엔터티 | 식별·관계 | 필수 메타데이터 |
|---|---|---|
| 고객사 | client_id, 사업장 소유 | 계약·자료 처리 허용·보관 정책, 연락처 별도 제한 영역 |
| 사업장 | client_id+site_id | 업종·규모·거래 단위·지역 필요한 수준·운영 단계 |
| 역할·접근 | client_id+role_id | 대표/담당/검수/고객 조회, 허용 목적·기간·회수 |
| 목표 | client_id+goal_id→사업장 | 최종 목표·직접 제공물·범위·합의 버전·승인자 |
| 지표 정의 | client_id+site_id+metric_id+definition_version | 계산식·단위·분모·포함/제외·영업일·적용 기간·검수 |
| 자료 | client_id+source_id+version | 출처·수집시각·기준기간·형식·해시·목적·승인·삭제일 |
| 진단·가설 | 목표+근거 자료 버전 | F/T/H/U, 대안·反증·확인자 |
| 실행·관측 | 목표+실험+지표 정의 | 담당·승인·시작/종료·사용·결과·다른原因·수정 |
| 보고·감사 | goal_id+report_id | 포함 자료 버전·생성·검수·승인·전달·수정/삭제 이력 |

같은 '재방문율'도 대상 고객·분모·관측창·제외가 다르면 metric_id/정의 버전을 다르게 둔다. 정의 변경 전후를 한 선으로 합치지 않는다. 고객 간 비교는 허용 근거·재식별 위험·집계 기준과 비교 가능성을 별도 확인하기 전 하지 않는다.

## CSV/XLSX 처리 계약

최초 열: row_key, site_id, metric_id, definition_version, observed_on, value. 지표 정의와 단위는 먼저 등록하며 값은 유한 숫자, 날짜는 ISO 날짜, 한 파일에서 키 중복 금지. 추가 개인정보 열은 거부한다. XLSX는 .xlsx만, 수식·매크로·외부 연결·잠긴 파일은 자동 실행하지 않고 거부/수동 확인한다. CSV는 UTF-8 BOM 허용, 지원하지 않는 인코딩은 재저장 요청. 원본은 변경하지 않는다.

수신→파일 크기/확장/내용→필수열/날짜/숫자/지표 정의→고객/사업장 일치→해시/행키 중복→pending 검수→사람이 기간·단위·원본 대조→approved→보고. 업로드 수신과 분석 완료를 분리한다. 오류 파일은 부분 적재하지 않고 전체 반려하며 오류 코드·행 번호만 알린다.

동일 source_id·동일 해시는 같은 버전으로 중복 수신 처리. 같은 source_id의 내용 변경은 새 버전과 재검수로 남기고 이전 승인 보고서를 조용히 덮지 않는다. 최신 버전이 승인 전이면 그 자료의 보고 생성을 중단한다. 지표 여러 source에 겹치면 기본 합산하지 않고 출처 우선순위를 사람이 정한다. 동일 지표·기간의 중복 행은 거부한다.

자동 수집을 붙일 때만 job_id·idempotency_key·입력 버전·실행 시각·상태·재시도 수·오류 코드·다음 시도를 기록한다. 네트워크/429/일시 5xx만 지수 지연·최대 횟수·기관 제한 안에서 재시도한다. 스키마/권한/동의 오류는 재시도하지 않고 사람 확인. 알림에는 고객 내용 없이 사건 코드·조치 링크만. 원본 변경 감지 시 영향 보고서를 재검수 상태로 돌리고 이전 전달 버전을 보존한다. 자동 수집·알림·복구 서비스는 아직 구현하지 않았다.

## 실제 고객 저장 전 통과할 문

- 고객별 계약·목적·항목·최소화·위탁/AI·국외 이전 해당 여부·보관기간/삭제 절차 확인. 직원·고객 제3자 자료 권한은 대표의 동의 하나로 충분하다고 가정하지 않음.
- 서버 인증으로 사용자→고객사 권한 확인, 모든 조회/쓰기/파일 키에 고객 경계 적용. URL/ID 변경·만료 링크·권한 회수·작업자 교체 테스트.
- 파일 접근 비공개, 저장/전송 보호, 악성 파일 검사·한도·사본/로그 최소화, 백업과 삭제 전파·복구 시험.
- 보고 링크 전달 대상과 권한 확인, 고객별 별도 공간. Notion 필터/뷰를 고객 격리로 사용 금지. 이번 Notion DB는 일반 템플릿·개발 상태용이며 민감 원본 없음.

## 경제·시장 1쪽 메모

목표와 연결되지 않는 지표는 넣지 않는다. 실제 최신 수치나 통계표 ID를 이번에 수집하지 않았으므로 보고서 값은 미입력이다. '2026-10-20 조회'가 '2026-10 자료'를 뜻하지 않는다.

| 노출 가설 | 공식 후보·확인할 것 | 고객 자료·반증 |
|---|---|---|
| 금리→이자 비용 | 한국은행 ECOS의 관련 금리, 지표 정의·주기 | 고정/변동·대출 잔액 집계·재산정일·실제 이자. 노출 없으면 영향 가설 제외 |
| 물가→매입/운영 원가 | KOSIS 소비자/생산 관련 가격 지표 중 품목 적합성 | 동일 품목 실제 매입단가·거래조건·구매량·배송비. 전국지수와 개별 원가 구분 |
| 환율→수입 원가 | ECOS 환율의 통화·매매 기준·평균/말일 | 수입 비중·결제통화·구매시점·재고·계약 전가. 환헤지·고정 계약 가능성 |
| 소비·고용→수요 가능성 | KOSIS 서비스/소매·지역 소비·고용 통계의 모집단·개정 | 업장 문의·방문·영업일·가격·경쟁·광고·계절. 지역·업종 불일치 표시 |
| 검색→관심 변화 | 네이버 데이터랩 공식 통합검색어 트렌드 | 키워드 선택·기간·성별/연령 등 필터·지역 한계. 상대 검색지수는 절대 고객 수·매출이 아님 |

메모 양식: 고객 목표 / 다음 결정 / 노출 경로 / 기관·통계표·항목·지역·주기·단위·계절조정 / 기준기간 / 발표일 / 조회일 / 잠정·수정 / 원본 URL / 실제 값(없으면 미수집) / 고객 지표·출처 / 적용 시차 / 다른 설명 / 가설과 관측 차이 / 운영자가 바꿀 판단 / 다음 발표·검토 조건.

경제 변화로 수정한 가설 기록: 변경 전 가설 ID·근거 버전→새 발표·고객 자료→유지/수정 이유→대표 결정→적용일→다음 점검. 외부 지표의 상관·시차만으로 인과를 확정하지 않는다. 투자 추천·자동 매매·자산 운용은 제외한다.

공식 출처(문서 조회 2026-10-20): [ECOS](https://ecos.bok.or.kr/)·[ECOS API](https://ecos.bok.or.kr/api/)·[KOSIS 통계자료 개발 가이드](https://kosis.kr/openapi/devGuide/devGuide_0201List.do)·[KOSIS 공지](https://kosis.kr/openapi/index/index.jsp)·[네이버 통합검색어 트렌드 API](https://developers.naver.com/docs/serviceapi/datalab/search/search.md). KOSIS는 apiKey·기관/표/항목·주기를 사용하며 갱신 공지와 현재 한도를 연결 전 재확인한다. ECOS API 상세 문서 본문은 이번 웹 도구에서 충분히 읽히지 않아 키 발급·호출 한도·정확한 시계열 ID는 미확인이다. 네이버 상대지수의 표본/기간 제한은 실제 요청 정의에 저장한다. 해외 통계는 고객 노출이 있을 때 공식 기관만 추가한다.

## AI 초안→별도 검수→사람 승인

1. 자료 적합성·AI 허용·마스킹을 사람이 확인하고 입력 묶음 ID와 해시를 고정한다.
2. ChatGPT 역할: 출처 번호 보존·요약·누락 질문·가설·매뉴얼/보고 초안. 없는 값을 생성하지 않도록 스키마와 '미확인' 필드를 둔다.
3. Claude 역할: 같은 입력/출처로 모순·누락·근거 없는 결론·개인정보·권한·실행 가능성 검토. 모델 사용만으로 독립 감사나 정답 보장 아님.
4. 운영자: 원본 사실·업종 맥락·금액/권한·범위·최종 전달 확인. 고객 대표: 목표·예산·현장 변경 승인.
5. 입력이 바뀌면 이전 검수 무효·재실행. 실패/빈 응답/형식 오류는 완료로 이동 금지. 반복 오류는 수동 작업으로 전환.

AI 실행 로그: run_id / client 작업코드 / input IDs·versions / 모델·프롬프트 버전 / 실행환경 / 시작·종료 / 토큰·실제 비용 / 오류·재시도 / 검수 지적 / 사람 승인 버전 / 전달 버전. 고객 개인정보를 로그에 쓰지 않는다. OpenAI·Anthropic 계정/키·결제·보관 설정·처리 조건은 미확인이라 이번에 실제 API를 호출하지 않는다. 기존 Claude 후속 호출 코드의 존재와 전체 검수 완료도 별개다.

## 계정·비용·구축 순서

| 단계 | 필요 계정/도구 | 현재 확인 | 비용 계산 항목 |
|---|---|---|---|
| 문서·사이트 | GitHub·Notion·기존 Render | 코드/문서 접근, 공개 사이트 확인. 관리 요금 미확인 | 현재 요금·사용 한도·유지 시간 |
| 실제 고객 시험 | 제한 저장 영역·권한 관리·동의/자료 목록 | 미준비, 실고객 이전 없음 | 저장/백업 GB·접근 로그·검수 시간·전문가 검토 |
| 보고 자동화 | 실행 서버/스케줄·오류 알림 | 합성 로컬 처리기만 개발 대상 | 실행 횟수·파일 수/크기·운영 점검·실패 복구 |
| AI 연결 | 별도 OpenAI/Anthropic API 계정·키·예산 | 미확인 | 입력/출력 토큰 단가×실제량·재시도·검수. 구독료와 API 별도 확인 |
| 외부 통계 | ECOS/KOSIS/필요시 네이버 앱·키 | 공식 문서 검토, 키·실제 호출 없음 | 호출한도·수집/정의 검수·개정 처리·저장 |

고정 견적을 만들 수 있는 사용량이 없다. 월 비용표는 저장/백업/전송·실행/알림·AI·외주·사람 시간과 실제 청구서를 넣어 계산한다. 본 작업에서 새 유료 계정·구독·배포 인프라를 만들지 않는다. 첫 운영자 한 건으로 수동 보고 시간과 실제 쓸모를 재고, 반복 부담이 확인된 단계만 자동화한다.
