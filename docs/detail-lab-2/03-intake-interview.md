# 단계별 접수·인터뷰 매뉴얼 v2

목적: 운영자가 답할 수 있는 질문으로 사업을 이해하고 불필요한 자료 요청을 줄인다. 대상: 인터뷰 담당자. 수정일: 2026-10-20. 버전: 2.0. 상태: 내부 시험 양식·실고객 미검증. 연결: S01→S04 후보. 작성: ChatGPT, 사실·적합성·동의 검수: 디테일랩 운영자. 출처: 이번 사용자 지시와 기존 노션 매뉴얼 v1. 재검토: 첫 응답시간·응답 포기·추가 질문 기록이 생길 때. 기존 센터 18문 원본을 대체하지 않는다.

## 공통 기록법

각 주장에 ID를 붙인다. F=확인된 사실(자료 ID·버전·기간·확인자), T=당사자 진술(역할·진술일), H=가설(반증 방법), U=미확인(누가·어떤 자료로 확인할지). 같은 문장 안에 섞이면 나눠 적는다. AI가 원본을 요약했어도 T가 F가 되지 않는다. 빈칸은 0이나 '문제 없음'으로 바꾸지 않는다. 범위가 다른 수치를 합치지 않는다.

대표와 직원 설명이 다르면 ①각 설명을 별도 T로 기록 ②같은 사건·기간·정의 선택 ③당사자에게 역할 기준으로 확인 ④현행 문서와 실제 처리 2건 등 가능한 기록 대조 ⑤기억·기준 변경·예외 가능성 확인 ⑥해결 안 되면 병기·판정 보류. 다수의 말이나 직급으로 진실을 정하지 않는다. 직원의 몰래 자료 제공·녹음·실명 평가를 요구하지 않는다.

민감 자료는 질문에서 먼저 제외한다. 필요한 경우 목적·항목·제공 권한·보관/삭제일·열람자·AI 처리 허용을 사전 확인하고 승인된 경로만 쓴다. 파일 이름의 실명도 제거한다. 원본 연락처와 작업 기록은 분리한다. 실제 고객 정보는 이 일반 매뉴얼/공개 GitHub/공유 DB에 넣지 않는다.

## 1단계: 최초 접수 (5~10분 목표, 측정 전)

고객 안내: '아는 만큼만 편하게 적어 주세요. 최근 한 장면이면 충분합니다. 이 단계에서는 직원·고객 실명이나 매출 원본 파일을 보내지 않습니다.' 현재 채널은 이메일. 아래는 새 온라인 Form 공개 전 검토 문안이다.

| ID | 고객 질문 | 목적·필수 |
|---|---|---|
| I01 | 어떤 업장이고 주로 무엇을 제공하나요? | 업종·상품 / 필수 |
| I02 | 운영 중·시작 준비·재시작 중 어디에 해당하나요? 사업장은 몇 곳인가요? | 단계·사업장 / 필수 |
| I03 | 대표를 포함해 함께 일하는 사람은 대략 몇 명인가요? 1/2~5/6~10/11명 이상/답하기 어려움 | 인력 규모 / 선택 가능 |
| I04 | 최근에 가장 걸렸던 한 장면을 설명해 주세요. 언제 어떤 일이 있었나요? | 추상적 불만을 사건으로 / 필수 |
| I05 | 무엇이 달라지면 이번 대화가 도움이 됐다고 느끼시겠어요? | 대표 목표 / 필수 |
| I06 | 그 일로 시간이 늘거나 놓친 일이 있나요? 모르면 비워 두셔도 됩니다. | 영향·급한 정도 / 선택 |
| I07 | 이미 바꿔 본 방법과 그 뒤 반응은 어땠나요? | 반복 처방 방지 / 선택 |
| I08 | 이 일을 바꿀 때 누가 결정하나요? 대표 본인/공동 결정/현장 책임자/미정 | 승인권·협력 / 필수 |
| I09 | 회신받을 이메일과 편한 호칭을 알려 주세요. 추가 대화는 이메일·예약 통화 중 어떤 편이 좋나요? | 최소 연락 / 이메일 필수·호칭/통화 선택 |

필수 자료: 답변 텍스트·회신 수단만. 선택 파일: 없음. 제출 형식: 텍스트. 동의 문구의 확정 필요 항목: 운영 주체·목적·항목·보관기간·거부 시 영향·삭제 요청·위탁/국외 이전/AI 사용 해당 여부. 일괄 동의로 민감 원본·직원 자료·AI 제공을 포괄하지 않는다. 법률 문구 최종 검토는 별도다.

자료 부족 시 후속 질문 하나만: 매출 고민이면 '문의·구매·재구매 중 어디가 달라졌나요?'; 효율 고민이면 '누구의 어떤 일에 시간이 걸리나요?'; 사례가 없으면 '다음에 생기면 무엇을 적을 수 있나요?'; 권한 미정이면 '누가 내부 적용을 승인하나요?'. AI는 허용된 작업본의 주제 분류·빈칸 표시만, 사람은 회신·적합성·급한 위험·범위 밖 의뢰 판단. 완료: 핵심 장면·원하는 변화·연락 가능성·결정자 상태를 기록하고 '인터뷰/추가 질문/범위 밖/보류'로 분기한다. 미회신을 거절 또는 수요 없음으로 집계하지 않는다.

## 2단계: 사업 이해 인터뷰

권장 진행안(시험): 접수 재확인 5분→운영 흐름 20분→강점·제약·목표 15분→메모 확인 5분. 실제 시간은 기록한다. 13개를 모두 순서대로 읽지 말고 접수에서 확인한 것은 건너뛴다. 녹음은 기본값이 아니며 별도 허용이 없으면 메모만 쓴다.

| ID·영역 | 먼저 묻기 | 후속·판단 용도 | 선택 자료·주의할 추측 |
|---|---|---|---|
| U01 시작 이유 | 이 사업을 시작할 때 무엇을 하고 싶었고 지금은 무엇이 중요해졌나요? | 바뀐 목표/포기할 수 없는 조건은? 방향 우선순위 | 창업 이유가 고객 구매 이유라고 가정하지 않음 |
| U02 상품·고객 | 가장 자주 선택되는 상품과 그 고객의 이용 이유는 무엇인가요? | 최근 구매 한 건은? 고객군·제공 단위 | 메뉴·가격표, 대표가 말한 인기와 거래를 구분 |
| U03 수익 | 돈은 언제 받고 제공은 언제 끝나나요? | 환불·할인·원가·결제/제공 시점 차이는? | 익명 월 집계, 현금 유입을 이익으로 보지 않음 |
| U04 사람 | 누가 어떤 일을 맡고 어디까지 결정하나요? | 겹치거나 아무도 맡지 않은 일은? | 역할표, 직함을 실제 권한과 동일시하지 않음 |
| U05 대표 일 | 대표가 하루 빠지면 무엇이 멈추나요? | 최근 부재 때 연락 한 건은? | 역할별 시간 메모, 대표의 높은 기준을 직원 무능으로 해석 금지 |
| U06 고객 여정 | 최근 문의 한 건이 이용 종료까지 간 순서를 말해 주세요. | 누구에게 무엇이 전달됐나요? | 익명 사건, 대표적 한 건을 전체 패턴으로 일반화 금지 |
| U07 시간 | 지난주 가장 오래 붙잡고 있던 일은 무엇인가요? | 몇 번/언제/기록이 없으면 다음 주 어떻게 셀까요? | 1주 시간표, 기억 시간을 실측으로 쓰지 않음 |
| U08 반복·예외 | 자주 다시 묻는 일과 드물지만 어려운 일은 각각 무엇인가요? | 일반 기준과 예외가 바뀌었나요? | 기준 문서 버전·사례, 예외를 항상 발생하는 일로 보지 않음 |
| U09 기존 개선 | 이미 시도한 방법과 잘 안 쓰인 이유는 무엇인가요? | 실제 사용자를 만나 볼 수 있나요? | 변경 전후 안내, 미사용과 효과 없음을 구분 |
| U10 강점 | 최근 만족스러웠던 일은 무엇이고 무엇 덕분이라고 보시나요? | 지켜야 할 고객 약속은? | 좋은 처리 사례, 이유는 가설로 남김 |
| U11 부족·제약 | 지금 고치기 어렵거나 걱정되는 것은 무엇인가요? | 예산·공간·직원 협력·계약 제한은? | 현황 요약, 불만을 곧바로 원인으로 보지 않음 |
| U12 미래 운영 | 6개월~1년 뒤 어떤 하루가 됐으면 하나요? | 계속 직접 하고 싶은 일/내려놓을 일은? | 숫자·기간은 희망 목표로 표기 |
| U13 개인 생활·도구 | 사업 밖 시간을 어떻게 쓰고 싶나요? 현재 쓰는 도구 중 일이 줄거나 늘어난 것은? | 응답·방문 가능 범위, 도구 관리자/내보내기 권한은? | 도구 목록, 개인정보·가족 사정을 요구하지 않음 |

필수 산출물: 한 장 사업 이해 카드(상품·고객·수익 시점·대표/현장 역할·대표 사건·잘되는 점·제약·자료 위치·미확인·다음 질문). 필수 파일은 없다. 선택 형식: 가명화 CSV/XLSX 집계·가격표 PDF·업무 흐름 그림 PNG·문서 발췌. 원본 전체 대신 필요한 열/페이지를 요청한다. 자료 요청마다 '어떤 판단에 필요한지/기간/단위/필수 여부/안전한 경로/대체 자료'를 쓴다.

직원 설명은 대표의 협력 확보와 당사자의 참여 의사·사용 목적이 정해진 뒤 별도로 듣는다. AI는 인터뷰 메모 정리·흐름 초안, 사람은 인용·사업 구조·역할·자료 권한을 확인한다. 완료: 대표가 카드의 사실관계를 고치고 목표 후보 1개와 필요한 심층 모듈 1~2개를 선택한다. 서명 요구가 아닌 사실 확인이며 아직 실행 합의가 아니다.

## 자료 요청서·진단 결과 양식

자료 요청서: 요청 ID / 연결 질문·판단 / 필요한 항목과 제외할 개인정보 / 기간·주기·단위 / 파일 형식 / 원본 작성 주체·권한 / 제출자 역할 / 안전한 제출 경로 / 보관·삭제일 / AI 처리 허용 / 미제출 시 대체/한계 / 고객 확인일.

사실표 행: 주장 ID / 원문 / F·T·H·U / 출처 ID·버전 / 기간·단위 / 상충 진술 / 반증에 필요한 기록 / 유지할 방식 / 사람 검수 상태·일자.

진단 결과: 이번에 본 범위→유지할 점→자료로 확인한 내용→다른 설명·누락→가설과 반증→우선순위 대안→선택할 실험→예상 위험·전문가 범위→대표 확인 질문. 완성 기준: 모든 결론에 출처 또는 미확인 표시, 가설마다 반증, 실행 전 고객 승인. 센터 베타는 기존 결과 1장·가설 최대3·30일 행동1 범위를 따른다.
