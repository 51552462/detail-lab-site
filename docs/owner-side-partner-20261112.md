## 바로잡은 중심

디테일랩은 운영하는 사람 곁에서 생각부터 실행까지 필요한 일을 나눠 맡는다. 고객이 직접 일하거나 혼자 운영해도 대상이다. 자리를 비울 수 있는 운영은 고객이 선택할 수 있는 여러 목표 중 하나다.

‘오른팔·분신’이라는 요청은 대외적으로 다음 행동으로 설명한다. 최근 이야기를 듣고 놓친 부분을 짚는다. 필요한 자료와 사례를 찾아 비교한다. 대표와 선택한 방향을 자료와 행동으로 옮긴다. 실제 사용과 반응을 관찰해 다음 판단을 돕는다. 상시 비서·전문 임원·모든 현장 업무 대행·무제한 연락으로 표현하지 않는다.

사용자가 말한 현장 경험, 아이디어 연결, 적용과 관찰의 선호는 작업 방법의 출발점이다. 타 업종 전문성·성과·객관성을 이미 입증했다는 근거로 쓰지 않는다. ‘객관적 판단’이라는 약속 대신 대표의 설명과 실제 기록, 다른 가능성과 불리한 근거를 대조하는 절차를 보여준다.

## 고객이 겪는 장면과 맡길 일

| 가상 장면 | 디테일랩이 할 수 있는 일 | 대표가 맡을 일 | 남기는 자료 |
| --- | --- | --- | --- |
| 열심히 하는데 가격·홍보·설명 중 무엇이 문제인지 모르겠다 | 최근 장면을 질문으로 정리, 허용된 기록·현재 안내·필요한 외부 자료 대조 | 원하는 변화·지킬 방향 설명, 선택과 적용 결정 | 판단 근거·선택지·장단점·미확인 사항 |
| 아이디어가 있는데 조사하고 만들 시간이 없다 | 합의한 질문의 조사, 자료 초안·수정, 적용 준비 점검 | 조건·예산·실제 사용 확인, 제작 방향 승인 | 비교 메모·실제 사용할 한 자료·담당과 일정 |
| 공들이는 과정이 고객에게 보이지 않는다 | 실제 제공과 현재 설명·고객 반응 비교, 안내 문구와 구조 정리 | 지키고 싶은 방식과 제공 조건 설명·승인 | 근거가 있는 강점과 고객 안내 |
| 대표에게만 결정이 몰린다 | 한 업무의 처리·승인·인계 흐름 확인 및 자료 정리 | 결정 권한·예외·현장 적용 승인 | 업무 기준·실제 사용과 누락 기록 |

모든 작업을 한 고객에게 제공하는 목록이 아니다. 새 유료 상품·자동 정기 관리·무료 베타 제공량 확대를 의미하지 않는다.

## 한 고민을 실제 작업으로 바꾸는 기록 양식

### 1. 먼저 듣기

- 최근 언제, 어떤 일이 있었나? 당사자의 설명과 확인된 기록을 분리한다.
- 지금 무엇을 결정해야 하나? 원하는 변화와 결정이 필요한 시점은?
- 대표가 지키고 싶은 방식과 이미 잘되는 부분은? 실제 장면이나 고객 반응이 있나?
- 이미 시도한 일, 직접 할 수 있는 일, 누군가 맡아주길 바라는 일은?
- 혼자 운영하면 직원 질문을 강요하지 않는다. 대표 본인의 선택·고객 흐름·반복 작업을 확인한다.

기록: 고객 코드 / 최근 한 장면 / 대표의 설명 / 확인 기록·출처·기간 / 원하는 변화 / 지킬 것 / 미확인 사항.

### 2. 답할 질문과 조사 범위 정하기

기록: 이번 질문 / 왜 필요한지 / 필요한 최소 자료 / 제출·열람·AI 처리 허용 범위 / 조사할 공개 자료 / 종료 기준 / 담당 / 일정·비용.

‘전체 문제를 알아서 해결’로 받지 않는다. 예를 들어 ‘매출을 올려주세요’라면 ‘최근 문의에서 구매로 이어지지 않은 구간을 확인할 수 있는가’처럼 이번 질문과 비교할 기록을 함께 정한다. 자료가 없으면 진단을 확정하지 않고 수집할 최소 기록을 정한다.

### 3. 디테일랩의 관찰과 아이디어 더하기

| 항목 | 기록할 내용 |
| --- | --- |
| 관찰 | 실제로 본 장면·인용 위치·기간. 들은 설명과 구분 |
| 연결한 생각 | 현장 경험·책·다른 분야 자료에서 가져온 질문 또는 방식 |
| 참고 출처 | 제목·발행/조회일·해당 부분. 찾지 못했으면 미확인 |
| 업장과의 차이 | 고객·상품·역할·자원·지역·규모 차이 |
| 선택지 | 유지 / 작은 수정 / 다른 방법. 얻을 것·부담·필요 조건 |
| 반대 설명 | 제안이 맞지 않을 가능성, 아직 없는 근거 |
| 대표의 결정 | 선택·보류·다른 방향 및 이유. 디테일랩 제안과 구분 |

관찰은 직원의 의도·성격·역량을 자동 평가하는 일이 아니다. 대표·직원 설명이 다르면 같은 사건과 시점으로 나란히 기록하고 허용된 자료와 다시 대조한다. 법률·노무·세무·의료 등 자격이 필요한 판단은 해당 전문가 범위를 확인한다.

### 4. 나눠 맡기

기록: 선택한 일 / 디테일랩의 조사·제작물 / 대표의 승인·현장 적용 / 실제 사용자 / 완료 기준 / 전달일 / 수정 횟수 / 회신·점검 일정 / 비용 / 제외 범위.

고객이 원하는 결과와 디테일랩 납품 책임을 구분한다. 매출 증가·판단 부담 감소는 목표일 수 있지만 결과 보장은 하지 않는다. 다음 행동과 담당을 정하고, 기다리는 승인·자료가 있으면 표시한다. 범위 변경은 추가 일정·비용을 설명한 뒤 결정한다.

### 5. 반응 보고 다음 선택

기록: 전달 버전 / 실제 사용한 장면 / 쓰지 못한 이유 / 고객·대표·담당자의 반응과 출처 / 비교할 기간·지표 정의 / 예상 밖 부담 / 다른 원인 / 유지·수정·중단 / 다음 확인일.

만족했다는 말, 자료를 전달한 사실, 실제 사용, 운영 결과는 각각 구분한다. 숫자가 없으면 수치와 상승률을 만들지 않는다. 기존 방식에서 잘되던 부분이 훼손됐는지도 확인한다. AI 초안은 원문·논리·출처·개인정보·범위를 사람이 검수한 뒤 전달한다.

## 홈페이지와 연결

- 메인 첫 화면: ‘혼자 붙들고 있던 고민을, 함께 풀어갑니다.’와 대표가 직접 상담하는 가격·안내 판단 예시.
- 메인·서비스 #alongside: 듣기·조사와 비교·나눠 맡은 실행을 가상 장면과 남는 자료로 설명.
- 서비스: 기존 두 지원 방식 유지. 조사와 판단 보조를 구체화하고 case-execution을 추가. 기존 case-sales/away/team/brand URL 보존.
- 결과물: 대표가 직접 상담하는 가상 보고서. 가격 인하를 먼저 권하지 않고 자료와 다른 원인을 검토. 맞춤 제작 예시와 무료 베타 포함량 구분.
- #impact: 판단·실행·강점·대표에게 몰리는 결정 4항목. 출처·역할·실제 사용·다음 판단을 설명하며 실제 고객 수치 없음.
- 그림: 고민 → 조사·선택 → 실행 → 반응. 목표는 판단의 여유·실행의 진척·사업의 색깔로 확장.
- FAQ: 대표 직접 운영·1인 운영 대상과 연락 범위를 설명.
