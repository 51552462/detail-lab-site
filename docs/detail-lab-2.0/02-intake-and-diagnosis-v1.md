# 디테일랩 2.0 | 통합 접수·심층 진단 매뉴얼 v1

기준: 2026-10-19. **내부 시험용 완성안**. 실제 고객의 동의·자료·유료 거래로 검증되지 않았다. 기존 센터 3곳 무료 베타의 18문과 이 매뉴얼은 별개이며 대체하지 않는다.

## 공통 진행 규칙

- 접수 전에 고객에게 필요한 질문만 한다. 직원·회원·거래처의 이름, 전화번호, 건강 정보, 계좌, 주민·사업자번호, 원본 대화 전문은 기본 접수에 받지 않는다.
- 기록 한 줄마다 `[확인된 사실]`(원본 번호·기간·단위), `[당사자 진술]`(누가 언제 말했는지), `[가설]`(반증 질문), `[미확인]` 중 하나를 붙인다. ‘직원이 안 한다’ 같은 평가문은 사건·기준·기록으로 다시 묻는다.
- 고객이 설명할 권한이 있는 자료만 받는다. 직원 설명이 다르면 각 진술을 별도로 적고 동일 기간의 안내문·업무 기록과 대조한다. 당사자에게 확인하고도 다르면 차이 자체를 결과에 남긴다. 무단 열람·몰래 녹음·근로자 평가를 요구하지 않는다.
- AI에는 동의와 계약상 허용 범위를 확인한 최소한의 가명 작업본만 전달한다. AI는 분류·누락 질문·초안을 돕고, 담당자는 출처와 원본을 확인한다. 목표, 민감한 판단, 고객에게 보낼 결론은 운영자와 대표가 확인한다.
- 자료가 없으면 ‘0’, ‘문제 없음’, ‘업계 평균’으로 채우지 않는다. 자료가 부족해 실행이 위험하면 심층 진단을 멈추고 필요한 자료·예상 시간·대체 방법을 알린다.

## 1단계: 최초 온라인 접수 (고객이 답할 질문)

아래 9개를 한 화면 또는 두 화면으로 사용한다. 이름과 회신 방법은 실제 Form을 공개할 때 별도 수집·동의 문구와 함께 최소한으로 받는다. 지금은 **새 Form을 공개하지 않았으므로** 기존 전 업종 이메일 문의 상담에서 질문 카드로 쓸 수 있다.

| 번호 | 고객에게 보일 문장 | 목적·필수 여부 |
|---|---|---|
| I01 | 어떤 일을 하는 업장인가요? 주로 파는 상품·서비스를 한두 개만 적어 주세요. | 업종·사업 모델 / 필수 |
| I02 | 지금 운영 중인가요, 시작을 준비 중인가요, 다시 시작하는 중인가요? 사업장이 여러 곳이면 몇 곳인가요? | 단계·사업장 수 / 필수 |
| I03 | 현장에서 일하는 사람은 대표를 포함해 대략 몇 명인가요? (1명 / 2~5명 / 6~10명 / 11명 이상 / 답하기 어려움) | 규모·인터뷰 범위 / 필수 |
| I04 | 요즘 가장 자주 걸리는 일을 **최근 한 장면**으로 설명해 주세요. 누구의 실명도 쓰지 않아도 됩니다. | 추상적인 문제를 상황으로 좁힘 / 필수 |
| I05 | 이번에 무엇이 달라지면 ‘진행할 가치가 있었다’고 느끼시겠어요? 아직 숫자가 없어도 괜찮습니다. | 고객이 원하는 변화 / 필수 |
| I06 | 그 문제 때문에 지금 어떤 일이 늘어나거나 놓치고 있나요? (시간, 재문의, 취소, 비용, 직원 혼선 등) | 영향 경로 / 선택 |
| I07 | 지금까지 바꿔 보거나 직접 확인한 것은 무엇이고, 결과는 어땠나요? | 중복 처방 방지 / 선택 |
| I08 | 이 문제를 함께 결정할 사람은 누구인가요? 대표 본인 / 공동대표·관리자 / 아직 정하지 않음 | 의사결정 권한 / 필수 |
| I09 | 답변 뒤 어떤 방식으로 먼저 이야기하는 편이 좋으세요? 이메일 / 통화 가능 시간대 / 미정. 이 단계에서는 파일을 보내지 마세요. | 부담·연락 방법 / 필수 |

**자료·형식:** 필수 파일 없음. 선택 자료도 여기에는 업로드하지 않는다. 접수 답변은 텍스트, 회신 이메일 1개만 별도 칸. 파일은 범위와 안전한 전송 방식을 합의한 뒤 2단계에서 요청한다. 개인정보 수집 목적·항목·보관기간·위탁/AI 처리·삭제 요청 경로를 새 Form에 명시하고 필요한 동의를 확보하기 전에는 이 문안을 사이트 Form으로 열지 않는다.

**추가 질문 트리거:** I04가 ‘매출이 안 됨’이면 ‘지난 2주 동안 주문/문의/방문 중 무엇이 달랐나요?’; I05가 ‘효율’이면 ‘누구의 어떤 업무 시간이 얼마나 줄면 좋나요?’; I08이 미정이면 ‘누가 적용을 승인할 수 있나요?’를 1개만 후속 질문한다. 사실·진술·가설 표기는 접수 원문을 그대로 보관한 별도 권한 영역에서 작업본으로 옮길 때 붙인다.

**AI/사람:** AI는 답변을 업종·요청·미확인으로 분류할 수 있다(권한 확인 후). 사람은 적합성·범위 밖 요청·회신과 다음 인터뷰를 결정한다. **완료:** 연락 가능성·핵심 장면·원하는 변화·결정권자 상태가 기록되고, 인터뷰/추가 질문/범위 밖 중 하나로 분기한다.

## 2단계: 사업 이해 인터뷰 (대화용 질문)

한 번에 모든 자료를 요구하지 않는다. 인터뷰 목표는 실제 운영의 지도를 그리는 것이며 해결책 확정이 아니다. 다음 12개 중 접수와 관련된 것을 먼저 묻고, 모르는 것은 ‘미확인’으로 둔다.

| 번호 | 질문 | 확인하려는 것 |
|---|---|---|
| U01 | 이 사업장에서 가장 자주 오는 고객은 어떤 이유로 오고 무엇을 고르나요? | 고객·구매 상황 |
| U02 | 가장 중요한 상품은 무엇이고 가격과 원가·제공 시간을 누가 정하나요? | 수익 방식, 제공 제약 |
| U03 | 문의에서 구매·제공·재방문까지 대표적인 한 건을 순서대로 설명해 주시겠어요? | 고객 여정과 담당 전환 |
| U04 | 현장에서 반복되는 일을 누가 맡고, 대표가 다시 확인하는 일은 무엇인가요? | 역할·반복 개입 |
| U05 | 최근에 잘 풀린 일 한 건과 막힌 일 한 건을 골라 당시 기록이 남은 부분을 알려 주실래요? | 강점과 문제의 대조 |
| U06 | 직원과 고객에게 알려 주는 기준은 어디에 있고, 최근 언제 바뀌었나요? | 문서·변경 관리 |
| U07 | 매출·문의·방문·재구매 등은 어디에 기록하고, 기간과 계산 기준은 무엇인가요? | 자료 접근성과 지표 정의 |
| U08 | 직원 채용·교육·교대·퇴사 때 반복해서 다시 설명하는 일은 무엇인가요? | 조직 흐름 |
| U09 | 쓰는 예약·결제·메신저·엑셀 도구는 무엇이며 각 도구의 관리자는 누구인가요? | 연동 가능성과 권한 |
| U10 | 고객에게 어떤 업장으로 기억되고 싶고, 실제 안내·경험과 다른 곳이 있나요? | 브랜드 의도와 경험 |
| U11 | 지금 바꿀 수 없는 제약은 무엇인가요? (예산, 시간, 공간, 계약, 인력 등) | 실행 가능성 |
| U12 | 자료를 누구와 공유할 수 있고 직원 확인은 어떤 절차로 진행해야 하나요? | 동의·접근·협력 |

**필수 자료:** 인터뷰 메모, 대표가 확인한 대표 업무 흐름 1건, 사용 도구 목록. **선택 자료:** 이름과 식별정보를 제거한 메뉴/가격표, 최근 안내문, 업무표, 익명 사례, 요약 매출·문의 집계. CSV·XLSX·PDF·PNG/JPG·문서 파일 중 필요한 것만 제안하고, 실제 저장 위치와 권한이 정해지기 전에는 메일 첨부를 요구하지 않는다. 파일별 기간·작성자 역할·버전·출처를 기록한다.

**충돌·빈칸:** 대표가 ‘모두 같은 안내’라 하고 직원이 ‘교대마다 다름’이라 하면 같은 업무 한 종류·기간을 정해 기준 문서, 실제 처리 두 건, 양쪽 설명을 대조한다. 원인이 아닌 불일치 상태만 적는다. 자료가 없으면 ‘마지막으로 그 일이 생긴 날짜/어디에서 기록하는지/어느 사람이 확인 가능하지’를 묻는다. **AI/사람:** AI는 흐름 초안과 빠진 질문만 작성; 인터뷰어가 인용·권한·민감정보를 확인한다. **완료:** 주요 상품·고객·담당·자료 위치·제약이 한 장의 사업 이해 카드에 기록되고 대표가 사실관계를 확인한다.

## 3단계: 목표에 맞춘 심층 진단

목표 하나에 1~2개 모듈을 선택한다. 여러 문제를 한 번에 진단하지 않는다. 아래 질문은 면담 시작점이고, 업종마다 거래 단위·예약·재고·현장 안전의 중요도가 다르다.

| 모듈 | 고객 질문 예시 | 최소 자료·분석의 함정 |
|---|---|---|
| 매출·고객 | 지난 한 달 문의가 구매로 이어진 과정을 세 건만 설명해 주실래요? 취소·재방문은 어떻게 기록하나요? | 기간별 문의·거래 건수, 가격 변경·영업일. 총매출만으로 원인을 단정하지 않음 |
| 운영·동선 | 일이 멈추면 누구에게 다시 묻고, 어떤 정보가 빠져 있나요? | 익명 업무 한 건의 접수→완료 기록. 일회성 예외와 반복 구분 |
| 사람·조직 | 맡은 일과 결정 권한이 서로 다르게 이해된 최근 사례가 있나요? | 역할표·안내 버전·당사자 허용 범위. 개인의 능력 평가로 해석하지 않음 |
| 브랜드·콘셉트 | 고객에게 하는 약속과 실제 제공에서 달라진 부분이 있나요? | 공개 문구·상품·상담 기록의 비식별 예시. 선호도와 구매 증거 구분 |
| 자동화 | 반복 작업 중 사람이 직접 판단해야 하는 부분은 무엇인가요? | 입력·출력 예시, 예외·실패 건수, 현재 비용. API 존재와 실제 사용 권한 구분 |
| 시장·환경 | 최근 외부 변화 중 어떤 일이 영향을 준다고 보시나요? 그때 업장 데이터도 달라졌나요? | 공식 지표의 발표/기준일과 업장 지표. 상관을 원인으로 쓰지 않음 |

**필수 자료:** 선택한 모듈의 최근 사건 최소 1건, 기존 처리 기준 또는 ‘기준 없음’ 확인, 고객이 사용할 수 있는 지표 정의. **선택 자료:** 고객 승인·가명화한 4~12주 CSV/XLSX 집계, 현장 동선 그림, 변경 전후 안내문, 시스템 export. 원본은 승인된 비공개 경로에만 보관한다. 자료를 모아 놓았다는 사실만으로 AI 입력을 허용하지 않는다.

**판정 기록:** `관찰: 무엇/언제/누가 확인/원본 번호` → `상충 설명` → `가능한 가설` → `반증에 필요한 기록` → `바꾸지 않고 유지할 점`. 두 설명이 다르면 해당 기간과 같은 정의의 기록으로 확인하고, 해결되지 않으면 ‘판정 보류’. 파일이 부족하면 분모·기간·누락 건·정의 변경을 묻는다. **AI/사람:** AI는 중복·누락·이상치 후보와 질문을 제시, 사람은 자료 사용권·정의·맥락·진단 범위를 검수한다. **완료:** 고객 목표에 필요한 사실/가설 표, 대표 확인이 필요한 항목, 다음 실험 후보와 중단 위험이 명시된다.

## 4단계: 공동 목표·작업 범위 합의

대표와 함께 아래 순서로 묻고 같은 문서에 답을 적는다.

1. **목표:** 지금 가장 바꾸고 싶은 한 가지는 무엇인가요? 왜 이 목표를 먼저 고르나요?
2. **기준선:** 시작 전 어떤 기간과 기록을 기준으로 삼을까요? 숫자가 없으면 어떤 기록부터 만들까요?
3. **변화 지표:** 변화가 일어났다는 것을 무엇으로 볼까요? 계산식, 단위, 분모, 제외 사례는 무엇인가요?
4. **행동:** 한 업무 흐름에서 무엇을 바꾸고, 무엇은 그대로 둘까요?
5. **책임:** 디테일랩이 만들고 확인할 결과물과 대표·직원이 결정·실행할 일을 각각 누가 맡나요?
6. **자원:** 투입 가능 시간, 비용, 필요한 직원 협력과 동의는 어느 범위인가요?
7. **점검:** 언제 다시 보고, 데이터가 없거나 부작용이 나면 무엇을 멈추거나 수정할까요?
8. **합의:** 포함/제외 작업, 전달 날짜, 연락·수정 횟수, 비용·지급·취소 조건을 문서로 확인할까요?

**필수 자료:** 3단계의 판정표, 대표가 확인한 기준선/미확인 사유, 결정권자. **선택 자료:** 적용 담당자의 가능 일정, 견적/외주 비용, 집계표. 파일은 승인한 장소에 보관하고 합의서에는 필요한 출처 식별자만 링크한다. 자료와 대표 설명이 다르면 서명 전 현재 기준을 재확인하고 상충 사실을 표기한다. AI가 결과물 초안을 만들 수 있으나 가격·계약·개인정보·최종 우선순위를 확정하지 않는다. **완료:** 대표와 디테일랩이 같은 버전의 목표·범위·지표·책임·재점검일을 확인한다. 합의가 없으면 적용 시작 상태로 옮기지 않는다.

## 실제로 사용할 기록 양식

### 사업 이해 카드

`사례 코드 / 업종·사업장 수 / 주상품·고객 / 최근 장면 / 현재 잘되는 방식 / 업무 흐름 / 대표·직원 설명 차이 / 자료 원본 번호·기간 / 모르는 점 / 다음 인터뷰 질문 / 담당자 확인일`

### 진단 표 (행마다 작성)

| 주장 | 유형(사실·진술·가설·미확인) | 자료 ID·버전·기간 | 다른 설명 | 반증 질문 | 판단 담당·상태 |
|---|---|---|---|---|---|
| 예: 교대 뒤 안내가 달랐다 | 진술 | 예시 문서 A v1, 날짜 미상 | 현재 기준은 같다는 설명 | 동일 주간 안내 두 건을 비교할 수 있는가? | 사람 확인 대기 |

### 목표 합의서

`고객이 원하는 최종 변화 / 디테일랩 직접 제공물 / 제외·전문가 의뢰 / 시작 기준선(없으면 수집법) / 지표 계산식·단위·기간 / 한 가지 실행 / 고객 결정자·현장 담당·디테일랩 담당 / 적용 시작·재확인일 / 예상 투입시간·비용 / 자료 접근·AI 처리 범위 / 수정 횟수·긴급 대응 / 중단 조건 / 두 당사자의 확인 버전·날짜`

### 1장 결과 템플릿

`이번에 본 범위 → 유지할 점 → 확인된 사실(출처) → 아직 확인할 것 → 가능한 가설(반증) → 합의한 행동과 담당 → 시작 전 기록 → 다시 볼 날짜·지표 → 수정/중단 조건 → 범위 밖 요청`. 기존 센터 베타를 수행할 때는 그 베타의 **가설 최대 3개·30일 행동 1개** 약속을 따른다.

## 첫 시험과 통과 기준

가명화한 실제 동의 고객 1건에 접수부터 합의서까지 사용한다. 각 질문에서 응답 포기·추가 질문 수, 사람 시간, 자료 부족, 잘못 분류한 사실, 고객이 결과를 이해했는지를 기록한다. 고객이 한 번에 답하기 어렵다는 반응이 나오면 질문을 2단계로 옮기거나 삭제한다. 실제 파일과 권한이 없으면 예시 입력으로 문서 구조만 검사하며 ‘고객 검증’이라고 쓰지 않는다.
