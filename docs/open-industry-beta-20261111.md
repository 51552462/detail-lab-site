# 업종 제한 없는 운영 점검 베타 — 모집·진행·축적 기준

목적: 다른 업종도 참여할 수 있게 하되, 어떤 조건에서 무엇이 쓰였는지 비교 가능한 기록을 남긴다. 대상: 디테일랩 운영자. 수정일: 2026-11-11. 버전: 1.0. 상태: 실행 준비·홈페이지 코드 구현, 새로운 무료 제공 약속은 공개 승인 전. 작성: ChatGPT. 모집·제공 범위·고객 자료 처리 승인: 디테일랩 운영자. 재검토: 첫 실제 접수·작업시간·적용 기록 또는 범위 변경.

## 1. 경력을 표현하는 기준

앞세울 근거는 업종 경력의 길이가 아니라 실제로 맡은 역할과 고객에게 적용할 작업이다.

고객용 제목: **대표의 결정과, 현장의 실행을 연결합니다.**

고객용 본문: 직원으로 일하고, 관리자로 현장을 책임지고, 직접 사업을 운영했습니다. 대표가 정한 방식이 담당자에게 어떻게 전달되고 고객에게 어떤 경험으로 이어지는지, 서로 다른 자리에서 운영을 바라본 경험이 디테일랩의 출발점입니다. 대표의 고민을 실제 업무 장면과 연결해 어디에서 일이 멈추는지 살핍니다. 이미 잘되는 방식은 남기고, 필요한 담당·기준·업무 자료를 구체적으로 정리합니다.

실제 헬스·PT 업종과 PT샵 운영 경험은 ‘경험의 출발점’에 남긴다. 여러 업종의 실적·전문가 자격·개선 성과가 있는 것처럼 쓰지 않는다. 배경 설명을 짧게 하는 것과 경력을 숨기거나 부풀리는 것은 구분한다.

대안: ‘직접 사업을 운영해본 파트너’는 공감은 쉽지만 작업 내용이 약하다. ‘전 업종 운영 전문가’는 현재 근거가 부족하다. 이 개정안은 역할 경험을 근거로 제시하고 실제 제공물을 바로 연결한다.

## 2. 모집 단위

- 접수 대상: 업종 제한 없이 현재 운영 중인 사업장의 대표·운영 책임자. 온라인·1인 사업 포함. 업종 예시는 자격 제한이 아니다.
- 진행 단위: 우선 한 사업장·최근 운영 문제 한 가지. 여러 업무는 추가 범위다.
- 사람 검토: 운영 중인지, 결정·실행할 역할이 있는지, 최근 장면과 원하는 변화가 구체적인지, 디테일랩의 경험·조사·시간으로 다룰 수 있는지 확인한다.
- 전문 자격 판단, 직원 평가·비난, 성과 보장 요청은 범위를 조정하거나 다른 전문가의 범위를 안내한다.
- 첫 운영 묶음 제안: 같은 문제 유형을 가진 서로 다른 업종 3곳 이내를 순차 진행. 이는 작업량 제한을 위한 운영 제안이며 현재 모집 인원 확정·잔여 좌석·선정 고객 수가 아니다. 고객 대응에 쓸 가용시간을 확인한 뒤 정한다.
- 기존 센터 3곳 베타와 새 대상의 슬롯을 임의로 합치거나 기존 참여 조건을 바꾸지 않는다. 같은 고객에게 같은 진단을 중복 작성하게 하지 않는다.

## 3. 공개 승인할 무료 제공 범위

접수 검토·필요한 추가 질문 → 결과 1장(강점·우선 보완·판단 이유·가능한 설명 최대 3개·미확인) → 실행 행동 1개(담당·적용 범위·시작일·기록·중단 기준) → 합의한 적용 시작일로부터 30일 후 확인 1회.

매뉴얼 여러 종 제작·방문·업무 대행·시스템 개발·상시 연락·월 정기 관리는 제외한다. 상담 후 별도 유료 제안을 하더라도 동의 없이 전환하지 않는다. 후기·사례 공개를 무료 참여의 대가나 선정 조건으로 삼지 않는다.

새롭게 추가되는 30일 후 확인 1회는 기존 센터 베타의 추가 약속으로 소급하지 않는다. 센터는 기존 18문·결과 1장·가설 최대 3개·30일 행동 1개 조건을 따른다.

## 4. 처음 고객에게 전달할 질문

처음에는 텍스트만 받는다. 문의에 이미 있는 내용은 생략한다.

1. 어떤 사업을 운영하고 무엇을 제공하나요?
2. 사업장 수와 함께 일하는 사람은 대략 몇 명인가요? 1인 운영도 가능합니다.
3. 최근 반복해서 걸렸던 일 한 가지는 무엇인가요? 언제 어떤 일이 있었나요?
4. 반대로 잘되고 있어 유지하고 싶은 방식은 무엇인가요?
5. 어떤 모습으로 달라졌으면 하나요?
6. 이미 해본 방법과 그 반응은 무엇인가요? 선택 질문입니다.
7. 이번 적용을 결정하고 실행할 역할, 가능한 시점은 언제인가요?

기존 브랜드 이메일로 문의한다. 직원·고객 실명·명단·매출 원본·계약서 전체를 요구하지 않는다. 제출 전 이름 대신 역할을 쓰도록 안내한다. 연락처는 운영 기록과 분리한다. 이메일 수신 자체를 분석·AI 처리·다른 고객 비교·홍보 공개의 포괄 동의로 보지 않는다.

## 5. 사업 이해와 심층 질문

`docs/detail-lab-2/03-intake-interview.md`의 공통 접수·인터뷰 방법을 사용한다. 센터 18문을 다른 업종에 이름만 바꿔 복사하지 않는다.

| 공통 문제 | 더 물을 질문 | 업종에 따라 달라지는 조건 | 최소 기록 |
| --- | --- | --- | --- |
| 반복 문의 | 누가 어떤 안내를 못 찾았나요? 답이 달라졌나요? | 예약·배송·수업·서비스 제공 단위 | 문의 장면·응답 기준·같은 문의의 정의 |
| 인수인계 | 무엇을 넘겼고 다음 사람은 무엇을 알고 있었나요? | 교대·담당 변경·외주·1인 작업 전환 | 맡은 역할·전달 항목·누락과 재작업 |
| 대표에게 몰린 결정 | 직접 처리할 권한과 필요한 정보가 있었나요? | 환불·재고·고객 약속·강사/디자이너 배정 | 확인 요청의 유형·승인 예외·발생 기회 |
| 상품·서비스 안내 | 고객이 기대한 것과 실제 제공이 어디서 달랐나요? | 상품 구성·수업 기간·계약·반품·온라인 이용 | 안내 버전·기대의 출처·실제 제공 기록 |
| 대표의 반복 업무 | 어디에서 같은 내용을 다시 입력하거나 확인하나요? | 업무 도구·고객 채널·1인/팀 운영 | 실제 작업 순서·중복·걸린 시간·예외 |

사실·당사자 설명·가설·미확인을 나눈다. 설명이 다르면 같은 사건과 기간을 선택해 현재 자료와 대조한다. 담당자 수나 직급이 사실 여부를 정하지 않는다. 필요한 업종 지식이 없으면 추가 조사·인터뷰를 업무에 포함하거나 범위를 좁힌다.

## 6. 완료와 재확인

| 단계 | 남기는 결과 | 완료 기준 |
| --- | --- | --- |
| 접수 | 사례 코드·문제·원하는 변화·역할·회신 상태 | 진행/추가 질문/범위 밖/보류의 이유 기록 |
| 사업 이해 | 상품·고객·업무 흐름·강점·제약 | 대표의 사실관계 확인, 살필 문제 하나 선택 |
| 결과 1장 | 강점·우선 보완·출처·가설·다음 행동 | 근거 없는 단정·누락된 미확인 없음, 사람 검수 |
| 실행 합의 | 담당·승인·범위·날짜·기록·중단 조건 | 대표가 적용을 결정, 기존에 잘되는 부분의 영향 확인 |
| 30일 확인 | 전달/실제 사용·어려움·반응·다른 원인 | 유지·수정·중단·판단 보류 중 다음 선택과 이유 |

미사용을 효과 없음으로, 연락 감소를 개선으로 곧바로 결론 내리지 않는다. 처리 누락·고객 혼선·직원 부담도 같이 확인한다. 약속한 결과와 사후 확인을 운영자 업무 목록에 남기고 실제 소요시간을 기록한다.

## 7. 쌓아야 하는 비교 기록

각 사례: 가명 사례 ID / 업종 / 제공 방식 / 1인·조직 규모 / 고객 접점 / 문제 유형 / 최근 사건 / 현재 기준 / 관측 기간 / 발생 기회(예약·문의·주문 등 분모) / 원본 출처 / 당사자 설명 / 지킬 강점 / 가설 / 다른 가능성 / 적용한 변화와 버전 / 담당·승인 / 실제 사용 / 지표 정의·단위 / 적용 전후 / 부작용 / 실패·미사용 이유 / 투입 시간 / 유료 추가 지원의 제안·수락·실제 결제 구분 / 다음 판단.

다른 업종끼리 예약 건수와 주문 건수, 영업일이 다른 총 횟수를 그대로 합치지 않는다. 같은 문제라도 제약이 다르면 별도 유형으로 남긴다. 사례 3곳은 전체 업종의 유효성이나 시장성을 입증하지 않는다. 같은 업종 안의 다른 조건과 같은 문제의 다른 업종을 차례로 비교한다.

## 8. 템플릿에 반영하는 방법

실제 자료 → 고객별 제한 기록 → 식별정보 제거·사용 허용 확인 → 반복되는 문제 후보 → 사람의 근거·예외 검수 → 공통 질문/자료 후보 → 버전 개정·변경 이유 → 다음 사례에서 사용 결과 확인.

자동 수신·자동 축적·자동 템플릿 갱신은 이번 구현에 포함되지 않는다. 고객 원문이 공통 프롬프트에 자동으로 들어가지 않도록 한다. 향후 자동화 시에도 사람 승인 전에는 고객용 원본을 바꾸지 않는다.

## 9. 공개 전 결정과 현재 확인

- 사용자 방향: 업종 제한을 넓히고 실제 다른 업종의 사례도 받는다. 이 방향은 확정 의도로 기록한다.
- 검토할 제공 약속: 한 문제·무료·결과 1장·실행 1개·30일 후 확인 1회. 이 구체 범위의 공개는 승인 전이다.
- 최초 동시 수용 수와 업무 가용시간, 고객별 일정·연락·자료 처리 안내는 진행 전에 정한다. 공개 페이지에 임의 납기나 남은 좌석을 표시하지 않는다.
- 현재 구현: 새 브랜드 소개, 홈페이지 통합 베타 카드, `/beta.html` 안내·7개 시작 질문·기존 이메일 문의/질문 복사. 기존 센터 Form·18문·개인정보 경로·유료 결제는 변경하지 않았다.
- 실제 신청·진행·고객 효과·매출·결제는 확인되지 않았다. 현재 공개 사이트의 제공 상태와 이 PR의 준비 상태를 구분한다.
