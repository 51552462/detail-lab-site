## 실행과 제공 범위

`pip install -r internal/ops_mvp/requirements-hosted.txt` 후 `python -m internal.ops_mvp.hosted`를 실행한다. Render에서는 문서화된 `RENDER_EXTERNAL_URL`, `PORT`, `RENDER_GIT_COMMIT`을 읽는다. 로컬 시험만 `DL_TRIAL_ORIGIN=http://127.0.0.1:10000`으로 실행한다. Waitress가 `0.0.0.0:$PORT`를 수신하며 `/health`는 부작용 없는 준비 상태와 소스 버전을 반환한다. 기존 `server.py` 루프백 시험 서버는 수정하지 않았고 프록시로 공개하지 않는다.

체험은 기존 `Workflow`와 `scenario` 함수를 호출한다. 방문자가 버튼을 누르면 서버에 준비된 가상 답변·지표만 들어간다. 접수→인터뷰→고객 확인→근거 구분→목표 양쪽 승인→실험→사용 관측→가상 집계 제출→행 검수→대표의 수정 결정→보고→종료 14단계를 기록한다. 고객 A/B/운영자 전환은 체험 기능이며 실계정 로그인이나 실제 당사자 동의가 아니다.

## 입력·접근과 임시 저장

- 웹 요청에는 `ack`, 고정된 역할 열거값, 단계 번호만 허용한다. 자유 문장·실제 연락처·외부 파일·고객 등록·기존 로컬 API 경로를 받지 않는다. 파일 제출 단계도 서버 소유의 14행 가상 CSV만 처리한다. 개인정보 정규식에 의존해 실고객 자료를 허용하지 않는다.
- 방문자마다 임의 256비트 쿠키와 독립된 임시 폴더/DB를 만든다. HTTPS 쿠키는 `__Host-`, `Secure`, `HttpOnly`, `SameSite=Strict`, `/` 경로를 사용한다. 변경 요청은 정확한 Host/Origin과 CSRF를 검사한다. 외부 주소는 환경 설정값만 신뢰한다.
- 최대 동시 체험 24개, 고정 수명 1시간. 다음 요청에서 만료된 서버 생성 임시 폴더만 정리한다. 재시작·무료 서버 중지 때는 더 일찍 사라진다. 원문 요청·연락처·쿠키는 앱 로그에 남기지 않는다. 플랫폼 HTTP 로그의 처리 방식까지 별도 검토했다고 하지 않는다.
- 하나의 체험에 접수 1건·자료 1버전·보고 3종만 만든다. 요청은 512바이트로 제한한다. 같은 단계 재전송은 이미 저장된 다음 상태를 반환해 중복 실행하지 않는다. 예상하지 못한 부분 실패는 완료로 표시하지 않고 새 체험을 안내한다. 분산 DB 롤백을 보장하지 않는다.
- 다른 방문자의 쿠키가 없으면 그 체험을 조회할 수 없다. 고객 B 역할에는 A의 기록을 반환하지 않는다. 가상 역할을 바꾸는 권한과 실고객 인증은 구분한다.

## 배포 구성

별도 Render Web Service, Python, `free`, Singapore, 자동 배포 끔. GitHub의 검수된 브랜치를 소스로 사용한다. 기존 홈페이지 Static Site와 트레이딩 서비스는 변경하지 않는다. 현재 무료 서버는 체험에만 사용하며 영구 보관소로 설명하지 않는다. 월 고정 컴퓨팅 요금이 없는 plan이어도 계정의 공유 무료 시간·빌드·전송량을 소비하며 실제 사용량/초과 요금을 조회한 것은 아니다.

## 실제 고객 운영에 남은 일

이 배포로 실고객 접수·민감자료 저장을 출시하지 않는다. 실제 작업을 계속 기록하려면 운영자/고객 계정과 초대·회수, 영구 저장·백업/복구·삭제, 업종/지표 정의, 자료 처리와 계약 조건을 정해야 한다. 기존 고정 합성 고객/지표를 단순히 실명으로 교체하는 것은 운영 전환이 아니다. 유료 서버·디스크나 관리형 DB를 선택하기 전 현행 가격과 월 한도를 검토한다. 이 체험에는 AI·경제 API·고객 발송·결제 연동이 없다.
