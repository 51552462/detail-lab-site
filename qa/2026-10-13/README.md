# 놓친 부분의 확인에서 판단·실행·재확인으로 연결

시작 main: `b2fd5d52516039463680b05502f6db1270f7a1a6`.

사용자의 최신 설명과 전날 반영된 운영자 답변을 대조했다. 대표·근무자 양쪽의 관점, 운영의 빈틈과 장점, 기록과 다음 행동은 기존 방향에 있었다. 다음 업무의 판단·결정·실행 담당과 재확인을 실제 기록에 연결하는 부분은 약했다. 고객에게 특정 인물·직함을 내세우지 않고 이 역할을 구체적인 도움으로 표현했다.

## 반영

- 홈 첫 소개, 다섯 분야 설명·공통 푸터·운영 경험을 정리했다. 매장 운영 뒤 다른 현장의 점장으로 일하며 관점을 넓히는 과정만 소개하고 현재 지역·근무처·이력서는 공개하지 않았다.
- 홈에 확인할 내용 / 누구와 정할지 / 쓴 뒤 다시 볼 기록의 연결을 추가했다.
- 전 업종의 방향을 관찰·선택 근거·업무 인계·재확인 네 단계로 설명했다. 실제 지원 범위·기간·비용은 문의 후 확인하는 상태다.
- 센터 자가점검과 직장 기록지에 선택적인 다음 행동 메모 세 칸을 추가했다. 사용자 작성 내용만 복사본에 함께 담는다. 직장 기록지는 수정 후 복사할 때 현재 입력으로 다시 생성하고 화면·복사·인쇄 내용에 같은 메모를 포함한다. 빈칸은 운영자가 판단하거나 실행했다고 채우지 않는다.
- 기존 가게·교대의 담당자·회신·7일 카드와 수업의 첫 대화·후속 확인을 소개의 공통 역할에 연결했다. 수업의 미작성 답·소개·예약 서비스를 만들지 않았다.
- 센터 18문, 직원 3~10명, 무료 3곳, 결과 1장·가설 최대 3개·30일 행동 1개, 가격·계약·개인정보 범위를 임의로 확대하지 않았다. PR #19는 별도로 남긴다.

## 검증

- 로컬 check_site.py: 12 HTML·링크·앵커·ID·인라인 JS 통과. git diff --check 통과.
- 기존 CI 사용 흐름에 센터의 빈 메모·직접 쓴 메모 복사, 직장 메모의 결과/복사 일치·수정한 최신 값 반영 검사를 추가했다. 실제 고객 자료 대신 합성 입력만 사용한다. 신청·결제·의견 양식을 제출하지 않는다.
- 이 환경에는 실행 가능한 Playwright 브라우저가 없다. PR CI로 실제 고객 경로와 모바일·PC 캡처를 검증한 뒤 직접 읽은 파일·관찰·미열람 범위를 기록한다.
- 노션 고객 안내와 내부 운영 기록은 같은 역할 및 현재 제공 범위로 맞춘다. 이를 효과·수요·유료 거래 검증의 완료로 보고하지 않는다.
- 병합·공개 반영과 최종 검사 결과는 실제 확인 후 PR에 남긴다.
