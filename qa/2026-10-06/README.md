## 변경 전후

| 영역 | 기존 표현의 중심 | 새로 확인하는 것 |
|---|---|---|
| 센터 | 역할·결정·기준이 있는지 | 판매 때 한 약속·잔여 수업·담당 변경·실제 정산이 같은지 |
| 가게·교대 | 다음 사람이 무엇을 하는지 | 단골 예외, 엇갈린 예약 기록, 내부 완료와 손님 해결의 차이 |
| 직원 | 근무 시간·급여 기준을 들었는지 | 전체 투입 시간, 취소·담당 변경의 지급 항목, 추가 역할과 부담 |
| 수업 대조 | 요일·시간·스타일 겹침 | 실제 가능한 세부 시간과 담당 변경·취소·포함 범위 추가 확인 |

결과에는 유지할 좋은 점의 근거, 실행 전 기록, 멈추거나 수정할 조건을 넣었다. 본인이 잘 처리했다고 답한 것은 자기보고이며 확인된 강점이나 고객 성과로 쓰지 않는다. 모든 unknown은 비교에서 제외하며 실제 사례 없는 화면과 복사본은 참고 카드일 뿐이다.

## 검증

- 로컬 정적 검사: 11개 HTML의 링크·앵커·ID·인라인 JS 통과.
- 순수 JS VM 검사: 48문/5개 선택지, 모든 최고·최저·unknown 답, 한 답만 확인한 낮은 값/최고 값, 부분 확인의 안내, 유지할 점·새 기록의 복사; 20개 분기 통과.
- 매칭 추가 질문 3개는 화면 렌더 및 복사 경로의 소스 포함을 확인했다. 실제 UI·동의 조작을 새로 수행한 검증은 아니다.
- 기존 고객 흐름 CI는 가상 입력에 unknown과 새 기록 복사를 추가했다. 실행 결과·SHA는 PR/Actions에서 독립 확인한다.
- 이 수정본의 모바일·데스크톱 캡처를 직접 열어 보지 못했다. 고객 반응·판매 효과·시간 절감·기능의 사용성 개선이 실증됐다는 뜻이 아니다. 기존 매칭 공개 UI 동의 단계의 권한 차단을 다른 수단으로 우회하지 않았다.
